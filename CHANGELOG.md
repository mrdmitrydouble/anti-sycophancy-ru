# Changelog

Все значимые изменения этого плагина фиксируются здесь.
Формат следует [Keep a Changelog](https://keepachangelog.com/); проект использует [семантическое версионирование](https://semver.org/).

## [0.3.0] — 2026-09-22

Критик, который не видел свой вход, не должен выносить вердикт. В реальной работе критиков иногда
вызывали с **путём к файлу вместо текста черновика**. Инструментов у них нет, прочитать файл они
не могут — и дважды (28.06 и 17.09.2026) критик **выдумал содержимое файла** и был готов вынести
вердикт по документу, которого не видел. В третий раз он честно отказался, но ответил `n/a`, а это
читается как «всё чисто». Правило «передавай текст внутри вызова» существовало только на словах;
0.3.0 превращает его в механизм с обеих сторон вызова. Чек-листы критиков не менялись.

### Добавлено
- **Страж входа** (хук `PreToolUse` на вызов субагента). Если вход критика нарушает шаблон —
  черновика нет или вместо него путь / «см. файл», фенс пустой или не закрыт, цитаты не в фенсах,
  тип запроса не одной нейтральной строкой, — вызов отклоняется до запуска критика, а вызывающий
  агент получает причину и готовый способ исправить. Других субагентов страж не трогает. Если сам
  страж не может отработать на вызове критика (нет Python 3.6+), вызов отклоняется: тихо
  выключенный страж — это отсутствие стража. `AS_INPUT_GUARD=off` — явный выключатель.
- **Протокол ответа критика.** Каждый вердикт заканчивается строкой
  `ЯКОРЬ: "<первые 10 слов черновика>"`. Без пригодного входа критик возвращает две строки —
  `СТАТУС ВХОДА: invalid(<причина>)` и прочерк — никогда `n/a`, `false`, `ok` или `continue`.
  У `n/a` остаётся одно значение: второй или отсутствующей стороны нет, а вход при этом валиден.
  Строку статуса в каждом ответе пробовали и убрали: в A/B-регрессии она сдвигала вердикт стража
  пары на пограничном кейсе.
- **Проверка вердикта** (хук `PostToolUse`). Каждый ответ критика, вызванного не в фоне,
  проверяется: только допустимые значения, якорь — дословный фрагмент реально отправленного
  черновика, нет следов вызова инструментов. Вызывающий агент получает
  `anti-sycophancy verify: VALID | INPUT INVALID | VERDICT VOID`. Оркестратор и скиллы используют
  только вердикты VALID; невалидный ответ `as-safety` считается необоснованным `continue`, поэтому
  детерминированный пол безопасности остаётся в силе.
- **Один повтор для исправления формата** (хук `SubagentStop`): если черновик у критика был, но он
  нарушил формат или якорь, его один раз просят ответить заново в строгом формате. Без зацикливания.
- `scripts/as_verify_verdict.py` — та же проверка как утилита командной строки и библиотека.
- Тесты — в основном репозитории: юнит-тесты и живые сквозные тесты.

### Изменено
- **Обезличивание закрыто на уровне среды.** У критиков теперь `omitClaudeMd: true`: CLAUDE.md и
  память проекта в них больше не загружаются. Раньше «обезличенный» критик мог прочитать имя
  владельца и правила проекта из собственного контекста. Также `maxTurns: 2`. Проверено, что
  `tools: []` действительно даёт критику ноль инструментов. Статус git и адрес почты аккаунта
  Claude Code по-прежнему передаёт любому пользовательскому субагенту — это описано в ограничениях.
- **Метрики пишет хук, а не модель.** Прежний хук `SubagentStop` не фильтровал агентов и считал
  любого субагента, а строку, которую должна была писать модель, на практике не писал никто.
  Теперь — ровно одна строка на прогон критика:
  `{"ts","event":"critic_stop","v","agent","tool_uses","status","anchor_ok","verdict","retried","warnings"}`
  — метки и действительность вердикта, никогда текст. `/as-metrics` читает и новые, и старые строки.
- **Служебные файлы не попадают в git механически, а не по совету из README.** Хук вносит
  `.claude/as-metrics.jsonl` и `.claude/.as-mode` в локальный для клона `.git/info/exclude`:
  ни один отслеживаемый файл не меняется, коммитить нечего, конфликтовать соавторам не из-за чего.
  Если один из файлов уже отслеживается, хук один раз об этом скажет.
- Файл режима: устаревшее значение `on` принимается как `auto`; любое неизвестное значение
  означает `off`, и об этом сообщается.

### Переход на новую версию
- `claude plugin update anti-sycophancy@anti-sycophancy`, затем перезапустите сессии Claude Code
  (агенты и хуки подхватываются при старте сессии).
- Хукам нужен Python 3.6+ в `PATH`. Без него вызовы критиков отклоняются с объяснением.
- Если `.claude/as-metrics.jsonl` или `.claude/.as-mode` уже закоммичены в репозитории, один раз
  выполните: `git rm --cached .claude/as-metrics.jsonl .claude/.as-mode`.
- Вызывайте критиков с текстом внутри вызова и не в фоне (несколько параллельно — можно):
  фоновые вызовы хук проверить не может.
- Старые строки метрик (`"event":"subagent_stop"`) остаются читаемыми, но это не прогоны критиков.

## [0.2.2] — 2026-06-24

Подготовка к релизу: закрыты замечания независимого предрелизного аудита
(1 блокер + 4 крупных + мелкие). Сам движок anti-sycophancy не менялся и уже был независимо
проверен (поведенческие 22/22, safety 12/12 escalate + 8/8 continue); этот релиз исправляет
упаковку и защитную обвязку вокруг движка.

### Исправлено
- **(блокер) Метаданные плагина теперь загружаются.** Взяты в кавычки `description:` во
  frontmatter файлов `agents/as-guardian.md`, `agents/as-solo-guardian.md`,
  `skills/as-couple/SKILL.md`, `skills/as-solo/SKILL.md`. Двоеточие без кавычек ломало
  разбор YAML, поэтому эти файлы загружались с пустыми метаданными — два межличностных
  стража теряли своё имя, `model` и `tools: []`, что молча отключало межличностного критика
  в режимах «пара» и «соло». `claude plugin validate` теперь проходит (exit 0).

### Добавлено
- **Кризисные ресурсы.** Канонический, учитывающий регион блок CRISIS RESOURCES, который
  escalate-путь выдаёт дословно (Россия 112 / МЧС +7 495 989-50-50 / Детский телефон
  доверия 8-800-2000-122; США 988 и 741741; международный findahelpline.com), с честным
  запасным вариантом — найти актуальную местную линию, если какая-то устарела.
- **Неклинический дисклеймер** в README (перед разделом «Установка») и однострочная версия,
  выдаваемая `/as-on`, `/as-couple`, `/as-solo`: не терапия, не диагностика, не служба
  экстренной помощи; защитный фильтр работает как может (без гарантий), и на него нельзя
  полагаться для безопасности.
- **Детерминированный safety-минимум.** При любом классе кризис-гейта (T1–T9) оркестратор
  никогда не оставляет ход с нулевой safety-поверхностью, даже когда single-LLM safety-критик
  возвращает `continue` — кроме случая, когда этот `continue` явно обоснован как прошлый
  нарратив/метафора.
- **Триггер запроса диагноза (C12-REQ).** Гейт теперь срабатывает, когда *пользователь*
  просит поставить диагноз (а не только когда черновик превышает полномочия), и
  направляет в психообразование вместо называния диагноза.
- **Раскрытие, что это ИИ** при эскалации («вы общаетесь с ИИ, а не с клиницистом»).
- Лёгкая самопроверка после переписывания на помеченных ходах; опциональный
  per-turn **nonce** на фенсах данных, передаваемых критикам.
- `homepage` в `plugin.json`; `license` в записи плагина в маркетплейсе;
  `LICENSE` продублирован в поддерево плагина; `CHANGELOG.md`.

### Изменено
- Раздел README `Use` уточнён (переключатели — это **скиллы**, вызываются по имени), а
  `Limitations` расширен (это не детектор кризиса; маршрутизация режима — решение модели;
  лексикон гейта валидирован на русском; один проход с лёгкой самопроверкой).
- Задокументировано сопоставление вердиктов рус→англ на пути метрик.
- Правки на честность формулировок в README/EVALUATION (смягчены «genuinely useful» и «large net
  correction»; отмечено, что ELEPHANT и Cheng et al. — смежные работы, а не независимые
  подтверждения).
- `.gitignore` теперь на всякий случай перечисляет per-project runtime-файлы.
- Усилен хук метрик `SubagentStop`: он один раз определяет целевую директорию и пишет
  только по абсолютному пути, чтобы лог не оказался в неожиданной папке.
